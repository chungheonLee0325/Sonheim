# 3.5. 전투 및 피드백 시스템

> ### 컴포넌트 기반 설계와 데이터 주도 방식으로 구현된, 타격감과 전략성을 모두 잡은 전투 시스템
> 
> *   **컴포넌트 기반 설계:** HP, 상태, 스킬 등의 핵심 기능을 독립적인 컴포넌트로 분리하고, 이를 조립(Composition)하여 플레이어, 몬스터 등 다양한 종류의 전투 객체를 유연하게 생성합니다.
> *   **데이터 주도 스킬 시스템:** 모든 스킬의 피해량, 속성, 넉백, VFX, SFX 등을 데이터 테이블에서 관리하여, 코드를 수정하지 않고도 기획자가 쉽게 새로운 스킬을 추가하고 밸런스를 조정할 수 있습니다.
> *   **피드백 중심 데미지 파이프라인:** 데미지 처리의 최종 단계에서, 물리적 반응(타격 경직, 넉백)과 시각적 피드백(플로팅 데미지, VFX)을 일관되게 제공하여, 타격감과 전략적 깊이를 극대화합니다.

## 3.5.1. 구현 기능 목록 (Feature List)

이 시스템을 통해 플레이어는 다음과 같은 전투를 경험하게 됩니다.

*   **전략적 전투 시스템**
    *   **속성 상성:** 모든 공격과 방어는 속성을 가지며, 속성 간의 상성에 따라 최종 피해량이 증가하거나 감소합니다.
    *   **속성 보너스 (자속기 시스템):** 자신의 방어 속성과 동일한 속성의 스킬을 사용하면, 최종 피해량이 1.2배 증가하는 보너스를 받습니다.
    *   **약점 공격:** 몬스터의 특정 부위(예: 머리)를 공격하면 \'약점\'으로 판정되어 더 높은 피해를 입힐 수 있습니다.

*   **타격감을 극대화하는 피드백**
    *   **물리적 피드백**
        *   **타격 경직 (Hit Stop):** 공격이 명중하는 순간, 게임 전체의 시간이 순간적으로 느려지며 타격의 무게감과 손맛을 극대화합니다.
        *   **넉백:** 공격의 강도와 스킬 데이터에 정의된 값에 따라, 피격된 대상이 자연스럽게 뒤로 밀려납니다.
    *   **시각적 피드백**
        *   **상황별 플로팅 데미지:** 일반 피해, 약점 피해, 속성 우위/열위 피해가 각각 다른 색상과 스타일의 숫자로 표시되어, 플레이어는 자신의 공격 결과를 즉시 시각적으로 인지할 수 있습니다.
        *   **풍부한 VFX/SFX:** 모든 공격에는 데이터 테이블에 정의된 고유의 타격 파티클 이펙트(VFX)와 사운드(SFX)가 동반됩니다.

*   **데이터 기반의 유연성**
    *   게임에 등장하는 모든 캐릭터와 몬스터의 스탯, 스킬 목록, 속성 등은 데이터 테이블에서 관리됩니다.
    *   모든 스킬의 상세 정보(피해량, 효과, 이펙트 등) 역시 데이터 테이블에서 관리되어, 기획자가 쉽게 새로운 스킬을 만들거나 밸런스를 조정할 수 있습니다.

## 3.5.2. 기술 상세 (Technical Deep Dive)

### 3.5.2.1. 아키텍처: 컴포넌트 기반의 조립식 전투 객체

Sonheim의 모든 전투 객체(`AAreaObject`)는 거대한 단일 클래스가 아니라, 여러 개의 독립적인 기능 컴포넌트를 \'조립\'하여 완성됩니다. 이는 언리얼 엔진의 컴포넌트 기반 설계를 적극적으로 활용한 것으로, 코드의 재사용성과 확장성을 극대화합니다.

*   `UHealthComponent`: 체력(HP)과 관련된 모든 로직을 담당합니다.
*   `UStaminaComponent`: 스태미나와 관련된 모든 로직을 담당합니다.
*   `UConditionComponent`: 상태 이상(무적, 은신 등)의 적용과 해제를 관리합니다.
*   `USonheimSkillComponent`: 스킬의 시전, 쿨다운, 데이터 관리 등 스킬 시스템의 모든 핵심 로직을 담당합니다.

### 3.5.2.2. 핵심 구현: FCustomDamageEvent를 활용한 컨텍스트 전달

언리얼 엔진의 기본 `ApplyDamage` 함수는 데미지 타입과 피해량 등 최소한의 정보만 전달할 수 있습니다. 하지만 Sonheim의 전투 시스템은 속성, 넉백, 타격 경직 등 풍부한 컨텍스트 정보가 필요했습니다. 이 문제를 해결하기 위해, `FDamageEvent`를 상속받는 `FCustomDamageEvent`라는 커스텀 이벤트를 정의했습니다. 이 이벤트는 스킬의 모든 정보를 담고 있는 `FAttackData` 구조체를 멤버 변수로 가지고 있어, 데미지 처리의 모든 과정에서 풍부한 컨텍스트를 활용할 수 있게 해줍니다.

`AAreaObject::TakeDamage` 함수는 이 `FCustomDamageEvent`를 받아, 단순한 피해량 외에도 공격의 속성, 넉백 강도, 히트스톱 유무 등 풍부한 컨텍스트 정보를 바탕으로 최종 데미지를 결정하고 다양한 피드백을 발생시키는 알고리즘의 뼈대를 정의합니다.

> [View on GitHub](https://github.com/chungheonLee0325/Sonheim/blob/main/Sonheim/Source/Sonheim/AreaObject/Base/AreaObject.cpp#L352)
```cpp
// Source/Sonheim/AreaObject/Base/AreaObject.cpp
float AAreaObject::TakeDamage(float Damage, const FDamageEvent& DamageEvent, ...)
{
    if (!HasAuthority() || bIsDead) return 0.0f; // 서버 권위 및 생존 여부 확인

    // 1. FCustomDamageEvent로부터 풍부한 컨텍스트 정보 추출
    FAttackData attackData;
    if (DamageEvent.IsOfType(FCustomDamageEvent::ClassID)) { /* ... */ }

    // 2. 방어력 계산 (자식 클래스가 재정의할 수 있는 Hook)
    float ActualDamage = HandleDefenceDamageCalculation(Damage);
    
    // 3. 약점 판정 및 보너스 적용
    bool bIsWeakPointHit = IsWeakPointHit(hitResult.Location);
    ActualDamage = bIsWeakPointHit ? ActualDamage * 1.5f : ActualDamage;

    // 4. 속성 상성 계산 및 보너스 적용
    float elementDamageMultiplier = 1.0f;
    for (auto defectElementalAttribute : dt_AreaObject->DefenceElementalAttributes)
    {
        elementDamageMultiplier *= USonheimUtility::CalculateDamageMultiplier(...);
    }
    ActualDamage *= elementDamageMultiplier;

    // 5. 최종 데미지로 HP 차감
    float CurrentHP = DecreaseHP(ActualDamage);

    // 6. 물리적/시각적 피드백 요청
    if (attackData.bEnableHitStop) ApplyHitStop(attackData.HitStopDuration);
    HandleKnockBack(DamageCauser->GetActorLocation(), attackData, m_KnockBackForceMultiplier);
    MulticastDamageEffect(ActualDamage, ..., bIsWeakPointHit, elementDamageMultiplier, attackData);

    return ActualDamage;
}
```

### 3.5.2.3. 회고 및 개선점: 템플릿 메서드 패턴을 활용한 확장성 확보

*   **설계 결정: 왜 템플릿 메서드 패턴을 활용했는가?**
    전투 시스템의 핵심은, 다양한 종류의 피격 대상(일반 몬스터, 보스, 넉백 저항 몬스터, 자원 등)이 각기 다른 방식으로 피해에 반응해야 한다는 점이었습니다. 이를 해결하기 위해, **템플릿 메서드 패턴** (Template Method Pattern)의 개념을 차용했습니다. 즉, 데미지 처리라는 알고리즘의 전체적인 골격은 엔진의 기본 피해 처리 프로세스(`ApplyDamage` -> `TakeDamage`)가 담당하고, 그 중 핵심적인 `TakeDamage` 가상 함수를 각기 다른 액터들이 자신만의 방식으로 재정의하도록 설계했습니다.

*   **구체적인 확장 사례:**
    `AActor`의 `TakeDamage`는 이 패턴의 핵심적인 **\'훅(Hook)\' 메서드** 역할을 합니다. `AAreaObject`(몬스터, 플레이어)와 `ABaseResourceObject`(자원)는 모두 `AActor`를 상속받지만, 각자의 목적에 맞게 이 함수를 전혀 다른 방식으로 재정의합니다. 이를 통해 다음과 같은 유연한 확장이 가능해졌습니다.
    *   **넉백 저항 몬스터:** `AAreaObject`를 상속받는 새로운 몬스터 클래스에서 `TakeDamage` 함수 내부의 `HandleKnockBack` 호출 부분만 비워두면, 다른 로직은 그대로 둔 채 넉백에만 저항하는 몬스터를 쉽게 만들 수 있습니다.
    *   **특수 약점 몬스터:** `IsWeakPointHit` 가상 함수를 오버라이드하여, 기본적으로 머리가 약점인 규칙에서 벗어나 \'등\'이나 \'꼬리\'가 약점인 특별한 몬스터를 구현할 수 있습니다.
    *   **자원 오브젝트:** `ABaseResourceObject`는 `TakeDamage`를 전투가 아닌 \'자원 생성\' 로직으로 완전히 재정의하여, 전투 시스템을 채집 시스템으로 완벽하게 재활용합니다. (참고: [[6.3 자원 시스템|6.3_Resource_System]])

*   **교훈:** 이 설계를 통해, 공격을 가하는 액터는 상대가 누구인지 전혀 신경 쓸 필요 없이 엔진의 기본 `ApplyDamage`만 호출하면 됩니다. 어떻게 반응할지는 전적으로 피격 대상이 스스로 결정하므로, 시스템 간의 결합도가 극적으로 낮아지고 코드의 재사용성과 확장성이 크게 향상되었습니다. 상속과 다형성을 활용한 디자인 패턴은, 복잡한 분기문 없이도 다양한 객체의 행동을 우아하게 처리할 수 있는 매우 강력한 도구임을 다시 한번 확인했습니다.
