# 7.1. 인벤토리 시스템 (Inventory System)

## 7.1.1. 설계 목표

인벤토리 시스템은 플레이어의 성장과 직결되는 핵심 시스템입니다. 아이템 데이터를 안정적으로 관리하고, 다른 시스템과 유연하게 상호작용하며, 멀티플레이어 환경에서 완벽하게 동기화되는 직관적인 시스템을 구축하는 것을 목표로 합니다.

1.  **데이터 영속성 (Data Persistence):** 플레이어가 죽었다 부활하더라도 인벤토리, 장착한 장비 정보가 모두 그대로 유지되어야 합니다.
2.  **데이터와 표현의 분리 (Separation of Data and Presentation):** 인벤토리 데이터 관리 로직(`InventoryComponent`)과 이를 화면에 표시하는 UI(`InventoryWidget`)를 완전히 분리하여, 서로 독립적으로 작동하도록 설계합니다.
3.  **직관적인 UX (Intuitive UX):** 드래그 앤 드롭, 우클릭 등 PC 게임 유저에게 익숙한 조작 방식을 통해 아이템 관리가 자연스럽게 이루어지도록 합니다.
4.  **안정적인 네트워크 동기화 (Robust Network Synchronization):** 아이템 획득, 버리기, 장비 교체 등 모든 인벤토리 변경 사항이 서버 권위 하에 처리되고, 모든 클라이언트에 정확하고 효율적으로 복제되어야 합니다.

## 7.1.2. 아키텍처

인벤토리 시스템은 데이터를 관리하는 `UInventoryComponent`와 이를 화면에 표시하는 `UInventoryWidget`을 중심으로, 데이터의 영속성을 보장하는 `PlayerState`와 월드 상호작용을 위한 `AChestActor` 등으로 구성됩니다. 특히, 네트워크 효율을 극대화하기 위해 언리얼 엔진의 **`Fast Array Serialization`** 기술을 핵심 아키텍처로 채택했습니다.

```mermaid
graph TD
    subgraph Server
        A(PlayerState) -- Owns --> B(InventoryComponent)
        B -- Holds --> C(FRepInventoryList<br/><b>(FastArraySerializer)</b>)
        B -- Modifies & Marks Dirty --> C
    end

    subgraph Client
        D(PlayerState Proxy) -- Replicates --> E(InventoryComponent Proxy)
        E -- Replicates --> F(FRepInventoryList Proxy)
        G(InventoryWidget)
    end

    C -- Delta Replication --> F
    F -- OnRep_RepItems() --> E
    E -- Rebuilds Local Mirror &<br/>OnInventoryChanged.Broadcast() --> G
    G -- Updates UI --> G
```

*   **`ASonheimPlayerState` (데이터 소유자):** `UInventoryComponent`를 생성하고 소유하는 주체입니다. `PlayerState`는 플레이어가 세션에 접속해 있는 동안 절대 파괴되지 않으므로, 여기에 인벤토리를 둠으로써 데이터 영속성을 보장합니다.
*   **`UInventoryComponent` (데이터 관리자):** `FRepInventoryList`라는 `FastArraySerializer` 구조체를 통해 인벤토리 데이터를 관리합니다. 아이템 추가, 제거 등 모든 데이터 조작 로직을 포함하며, 서버에서만 데이터 변경이 일어나도록 제어합니다.
*   **`UInventoryWidget` (UI 표현):** `InventoryComponent`의 데이터를 기반으로 슬롯들을 생성하고 갱신하는 UI 위젯입니다. 사용자 입력을 받아 `InventoryComponent`에 작업을 요청하는 역할만 수행합니다.
*   **`AChestActor` (월드 컨테이너):** 월드에 배치되는 보관함입니다. 자체적으로 `InventoryComponent`를 가지며, 서버 권위 하에 잠금(`bIsOpen`, `CurrentUser`)을 관리하여 여러 플레이어의 동시 접근을 막습니다.

## 7.1.3. 핵심 구현 및 UX 기능

#### 1. 효율적인 데이터 복제 및 UI 자동 업데이트 (`FastArraySerializer`)

단순히 `TArray` 전체를 복제하는 대신, `FFastArraySerializer`를 사용하여 네트워크 효율을 극대화했습니다. 이 방식은 배열 전체가 아닌, **변경된 아이템 슬롯만** 클라이언트에 전송합니다.

1.  **[Server]** 서버의 `InventoryComponent`에서 아이템이 추가/삭제/변경되면, 해당 슬롯을 `MarkItemDirty()`로 표시합니다.
2.  **[Engine]** 언리얼 엔진의 리플리케이션 시스템이 "Dirty"로 표시된 슬롯의 데이터만 네트워크를 통해 클라이언트로 전송합니다.
3.  **[Client]** 클라이언트에서 데이터 수신이 완료되면, `UPROPERTY`에 지정된 `OnRep_RepItems` 함수가 자동으로 호출됩니다.
4.  **[Client]** `OnRep_RepItems` 함수는 복제된 데이터를 바탕으로 클라이언트의 로컬 인벤토리 배열을 재구성하고, `OnInventoryChanged` 델리게이트를 방송합니다.
5.  **[Client]** `InventoryWidget`은 이 델리게이트를 구독하고 있다가, UI를 자동으로 갱신합니다.

#### 2. 드래그 앤 드롭 (클라이언트 예측 포함)

플레이어 경험에 매우 중요한 드래그 앤 드롭 기능은 **클라이언트 예측(Client-Side Prediction)** 기법을 통해 구현하여, 네트워크 지연이 있는 환경에서도 부드러운 UI 경험을 제공합니다.

1.  **UI 예측:** 플레이어가 아이템 드롭을 완료하면, UI는 즉시 아이템이 옮겨진 것처럼 **시각적으로 먼저 변경**됩니다.
2.  **서버 요청:** 동시에, `Server_SwapItems`와 같은 Server RPC를 호출하여 서버에 실제 작업을 요청합니다.
3.  **서버 검증 및 실행:** 서버는 요청이 유효한지 검증하고, 실제 데이터 배열을 변경합니다.
4.  **상태 동기화:** 서버의 데이터 변경 사항은 `FastArraySerializer`를 통해 모든 클라이언트에 효율적으로 전파됩니다. 클라이언트는 이 최종 데이터를 받아 자신의 UI를 다시 한번 정확한 상태로 갱신합니다. 만약 서버가 요청을 거부했다면, UI는 원래 상태로 되돌아갑니다.

#### 3. 우클릭 빠른 장착 및 안전한 아이템 삭제

*   **우클릭:** 아이템을 우클릭하면, 해당 아이템의 종류에 맞는 장비 슬롯에 즉시 장착되거나 해제되는 편의 기능을 제공합니다.
*   **안전한 삭제:** 아이템을 버리거나 파괴할 때, 수량을 조절할 수 있는 확인 팝업을 통해 사용자의 실수를 방지하는 2단계 확인 절차를 거칩니다.

## 7.1.4. 구현 경험 및 최적화

#### 메모리 관리 (Object Pooling)

*   **문제:** 월드에 대량의 아이템을 드롭할 때마다 `ABaseItem` 액터를 계속 생성하고 파괴하는 것은 성능 저하를 유발할 수 있습니다.
*   **해결 방안:** 자주 사용하는 아이템 액터를 미리 생성해두고 필요할 때마다 재활용하는 **오브젝트 풀(Object Pool)** 을 도입하여, 액터 생성/소멸에 드는 비용을 최소화하고 성능을 최적화했습니다.
